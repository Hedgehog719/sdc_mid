## 1. GNSS 的使用

- Track01、Track02 可以用 GNSS 做 sensor fusion，例如當 NDT 等 scan matching 的初始位姿。這仍然是合理、合乎規則的做法。
- 但助教重新說明競賽的核心目標：**用點雲對預建的 LiDAR 地圖做配準，自己估出車輛位姿**。直接用 GNSS 位姿等於多了全域定位先驗，成績會變成比較依賴 GNSS，而不是配準能力。
- 因此 **Track03 不提供 GNSS pose**。

## 2. Track02 地圖的 `tl`、`th` 時間欄位

- 助教處理資料時疏失，Track02 的 `map.pcd` 沒有移除 `tl`、`th` 這兩個時間欄位。我們確認過：`FIELDS tl th x y z intensity`，Track01 沒有這兩欄。
- 這兩欄可能記錄了每個 LiDAR 點的觀測時間，會透露建圖過程和建圖車的軌跡。助教說可信度沒有驗證過，請審慎使用，不要當成可靠的定位依據。
- **我們的情況：沒有用到。**
  - `tools/map_to_npy.py` 只保留 x、y、z、intensity。
  - `tools/clean_map.py` 移除建圖車停車時的掃描，用的是點在檔案裡的記錄順序，沒有讀 `tl`/`th`。

## 3. Leaderboard 探測與正式成績

- **允許**：一般的參數調整、模型或流程之間的比較。
- **不得作為正式評分或排名的依據**：用多次提交的分數，系統性調整軌跡位置或角度，反推隱藏的定位誤差再修正。這種 leaderboard-based fitting 並沒有改善演算法本身，只是間接推估 ground truth。
- 助教在討論區另外補充：
  - 分段探測或分段修正同樣不可以。
  - 可以指定一份「核心定位流程直接產生、沒有用探測修正」的提交作為評分對象。
  - 報告裡可以把 leaderboard-feedback 方法當成有趣的競賽策略或分析來寫。
- **對我們的影響：**
  - 以下檔案不能當最終評分檔：
    - board 最佳化的檔案：0.17429（`t2_opt10`）、0.41123（`t1_opt11`），以及其他 `opt*`。
    - 各種探測檔。
    - `t2_p20tuned_bestyaw`（0.20）：它的 yaw 取自 0.17 那份檔案。
  - **最終要指定純流程的輸出**：目前是 `submissions/day7/track1/t1_pipe_v5.csv`、`submissions/day7/track2/t2_pipe_v5.csv`，之後若有改進版再替換。
  - Kaggle 從 10/20 起分數只顯示到小數點後 2 位，精確探測本來就已經做不到了。

## 5. 評分方式

總分 = 競賽排名（最高 56）+ 報告（助教評，30）+ 簡報（Bob 評，20）

**競賽排名**：每個 track 依名次給分再乘上權重 r，三個 track 加總。Track1、2 的 r = 0.3，Track3 的 r = 0.4。

| 前 50% | 42 | 12.6 | 16.8 |

## 6. 對我們的意義與優先順序

1. **Track03 的權重最高（0.4），而且考的是泛化能力。**
   - 我們現有的流程很依賴 GNSS：起始位置、偏差模型、前後方向。T3 要改成不靠 GNSS：
     - 用地圖做全域初始化。先看 T3 有沒有提供初始猜測，T2 資料夾裡有 `init_guess.txt` 可以參考。
     - 用影像對地圖做比對：車道標線（BEV、影像空間）已經不需要 GNSS。
     - fix 和 fix 之間的連續運動，要靠 IMU（如果有提供）或視覺里程計。
   - 已知 3cameras_ply 的問題，T3 的前相機點雲可能也有：尺度每幀約 4% 雜訊、沿路漂移 ±9%，每幀還有 1–1.6° 的扭曲。直接拿來做 scan matching，前後誤差約 0.5 m。要用的話，需要先做時間平滑、用 IMU 或運動當比較器把壞幀挑掉，或者自己用三台相機重建。
   - **10/22 一拿到資料就先確認**：有沒有 IMU、有沒有初始位姿、PLY 的座標系和尺度。
2. **Public 只看前 10–30%**，public 分數不能代表整條軌跡。要靠本地標準驗證，例如 NIS、fix 時間一致性、IMU 加速度一致性、疊圖檢查，不要對著 public 分數調參。
3. **Track01、02**：最終指定 pipeline v5 或之後的改進版。目前的改進方向：
   - 前後方向：專門比對停止線、斑馬線、虛線端點這類橫向標線。
   - 彎道的 yaw 偏差。
   - 起步段收尾。
4. **報告與簡報（50 分）**：把這次的方法整理進去，包括：
   - 地圖清理：移除車頂層、Laplace 填補起步段空洞、錯位板塊修正。
   - fix 時間一致性檢查。
   - 用 NIS 選擇雜訊參數。
   - IMU 加速度輔助的 RTS。
   - 相機點雲誤差分析與 IMU 比較器。
   - leaderboard 回饋方法：照助教的說法，當成競賽策略與分析來寫，不作為正式成績。
